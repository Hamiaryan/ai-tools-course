    What is an AI Agent?↗

    A chatbot answers one question at a time. An agent receives a goal and autonomously steps through to reach it.

    16:54RobinExercises for this video →

    More about this video

    A chat assistant answers one question at a time. An agent is given an objective and takes multiple autonomous steps to accomplish it. This video explains the difference, agent internals, and how to monitor them safely. In the video: - Differences between chat vs. agent - The agent loop: plan, act, observe, iterate - Tool use: running code, reading/writing files, web search, API calls - Step-by-step example: an agent isolating and patching a bug - Levels of autonomy, and what agents excel at vs. struggle with today - Risks: compounding errors, infinite execution loops, overly broad permissions Three takeaways: 1. Always start in an isolated workspace, never in production code 2. Grant the agent only the minimum required tools and permissions 3. Verify what the agent actually changed, not just its summary text Food for thought: Consider a repetitive, well-scoped task in your daily work. Could an agent do it, and what tools would it require?

  11. 10

    Ethical and Security Risks of AI Coding↗

    Every time you interact with an AI assistant, you send data and receive code in return.

    15:54Zane

    More about this video

    Every time you use an AI assistant, you transmit context and receive generated output. Virtually all security and ethical risks reside in these two steps. In this video, we trace code from your editor to deployment. In the video: - What gets transmitted? PII, secret keys, and internal data sent with prompts, and GDPR implications - What comes back? Common vulnerabilities in generated code, including hallucinated package dependencies (package hallucination / typosquatting) - Concrete example: an SQL-vulnerable function vs. a parameterized secure function, both passing unit tests - Who bears responsibility? You, your engineering team, and your organization Rule of thumb: Never paste anything into an AI assistant that you wouldn't email to an external vendor. Food for thought: Think about the last snippet you pasted into an AI. Could you have emailed that exact data to an external provider without asking permission?

Treat AI compliance with the same rigor as cybersecurity and data privacy Official timeline available at artificialintelligenceact.eu

    How to Critically Review AI-Generated Code↗

    Passing tests only prove that the code satisfies those specific test cases.

    12:51Zane

    More about this video

    Passing tests mean code does what tests check. It does not prove it does what it is supposed to. This video covers the critical five minutes between an AI producing code and you committing it. In the video: - Why reviewing AI-generated code demands a distinct mindset from reviewing human code - Six questions every developer must ask before committing - Real-world case: AI generating discount calculation code with unit tests. 5 of 5 tests pass, yet code review uncovers 3 critical bugs. - Three practical habits: request smaller diffs, intentionally test failure paths, and log recurring AI blindspots Six questions before committing: 1. Does the code truly solve the actual problem? 2. Can you explain every single line? 3. Do tests fail when code is modified incorrectly? 4. How are edge cases and invalid inputs handled? 5. Is the implementation secure and sanitized? 6. Does it align with existing project architecture? Food for thought: Consider the last AI code you merged without changes. Which of these six questions would have been hardest to confidently answer 'yes' to?
