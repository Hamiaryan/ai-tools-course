Modul 01

Kursintroduktion & AI-verktyg och kodassistenter – översikt

Bekanta dig med de tre verktyg vi använder i kursen

Du behöver inte förstå allt på djupet redan nu — målet är att känna igen namnen och grovt veta vad som skiljer dem åt.

  • GitHub Copilot — Vad är GitHub Copilot? (~5 min)
    Officiell introduktion till Copilot: inline-komplettering, chatt och var verktyget används. Det mest spridda verktyget i sin kategori.
  • Cursor — Introduktion (~5 min)
    Cursor är en hel kodredigerare byggd kring AI. Sidan ger en snabb översikt av Tab-komplettering, Chat och Agent-läge.
  • Claude Code — Översikt (~5 min)
    Anthropics terminalbaserade, agentbaserade kodverktyg. Fungerar annorlunda än de två ovan — ingen inline-komplettering, mer självständigt agerande.

Modul 04

Testning och dokumentation med AI-stöd

Tester som faktiskt kontrollerar något

Gröna tester betyder att koden gör det testerna kontrollerar, inte att den gör rätt. De här sidorna handlar om att skriva tester och dokumentation som går att lita på. Alla tre är på engelska.

  • VS Code: Test existing code with AI (~15 min)
    Steg för steg: låt en agent föreslå testfall utifrån kraven, låt den skriva testerna utan att ändra koden, och granska sedan att testerna kontrollerar rätt sak. Sidan förklarar också varför det förväntade värdet inte ska räknas ut med funktionen som testas.
  • Martin Fowler: Test Coverage (~5 min)
    Testtäckning visar vilka delar av koden som inte testas alls. Fowler förklarar varför en hög siffra ändå inte betyder att testerna är bra.
  • PEP 257: Docstring Conventions (~10 min)
    Pythons riktlinjer för docstrings, kommentaren som beskriver vad en funktion gör. Läs avsnitten om enradiga och flerradiga docstrings. Skriver du C# eller Java finns motsvarande regler för XML-kommentarer och Javadoc.

Modul 05

Promptbaserad interaktion: tydliga instruktioner, krav och mål

Skriv instruktioner som går att arbeta efter

En bra prompt är en bra beställning. De här sidorna visar samma principer som modulens videor, med andra ord och andra exempel. Alla fyra är på engelska.

  • GitHub Copilot: Prompt engineering (~10 min)
    Konkreta råd om att skriva promptar: börja med målet och lägg sedan till kraven, ge exempel, dela upp stora uppgifter och undvik tvetydighet. Råden gäller alla AI-verktyg, inte bara Copilot.
  • Claude: Be clear and direct (~5 min)
    Ett kort avsnitt med samma tanke som kollegatestet: visa prompten för en kollega som inte vet något om uppgiften. Blir kollegan förvirrad, blir modellen det också.
  • Martin Fowler: Given When Then (~5 min)
    Förklarar formatet Givet–När–Då, som du använder när du skriver acceptanskriterier: utgångsläget, det som händer och resultatet du väntar dig.
  • Claude Code: Let Claude interview you (~5 min)
    Ett kort avsnitt om att låta verktyget ställa frågor innan det börjar bygga, så att oklarheterna kommer fram tidigt. Samma idé som i övningen Låt AI:n fråga.

Modul 06

Promptteknik i praktiken

Exempel, iteration och promptar du sparar

Den här modulen är praktisk övning, så läsningen är kort. Alla tre sidor är på engelska.

  • VS Code: Write effective prompts (~5 min)
    Ett kort avsnitt med vanor som fungerar: var tydlig med indata, utdata och begränsningar, dela upp stora uppgifter, ge förväntat resultat så att AI:n kan kontrollera sig själv, och förfina med korta uppföljningar i stället för att börja om.
  • Claude: Use examples effectively (~5 min)
    Varför några väl valda exempel i prompten styr format och ton bättre än en lång beskrivning, och hur bra exempel ser ut.
  • VS Code: Use prompt files (~10 min)
    Hur du sparar en prompt som fungerar som en fil i projektet, och kör den igen med ett kort kommando. Ett sätt att göra din promptmall återanvändbar.

Modul 07

Vad är en AI-agent?

Agentloopen, verktygen och hur mycket agenten får göra själv

De två första sidorna är korta förklaringar av begreppen. Den tredje är längre och går djupare. Alla tre är på engelska.

  • VS Code: Understand AI agents (~10 min)
    Förklarar agentloopen: agenten samlar information, gör något, kontrollerar resultatet och upprepar tills målet är nått. Sidan visar också hur du behåller kontrollen.
  • VS Code: Understand tools in AI agents (~10 min)
    Vad ett verktyg är för en agent, till exempel att läsa filer eller köra kommandon. Sidan visar hur du styr vilka verktyg agenten får använda, och när den måste fråga dig först.
  • Anthropic: Building effective agents (~15 min)
    Skillnaden mellan ett fast arbetsflöde och en agent som själv väljer sina steg. Läs början och avsnittet om agenter: när de passar, och varför ett fel kan följa med genom flera steg om agenten får gå för långt utan kontroll.

Modul 08

Bygg din första enkla AI-agent

Ge agenten en mapp, godkänn stegen och spara arbetssättet

De två första sidorna handlar om att behålla kontrollen över en agent. De två sista handlar om färdigheter (skills), alltså arbetssätt som agenten kan använda igen. Alla fyra är på engelska.

  • Claude Code: Extend Claude with skills (~10 min)
    När det lönar sig att spara ett arbetssätt som en färdighet, och hur en sådan fil ser ut. Läs inledningen och exemplet där en första färdighet skapas. Resten av sidan är fördjupning.

Modul 09

AI i utvecklingsflödet: CI/CD och teamarbete

AI föreslår, pipelinen verifierar, du avgör

Två sidor om hur automatiska tester och leveranser fungerar, och två om att granska kod innan den slås ihop med resten. Alla fyra är på engelska.

  • GitHub Docs: Understanding GitHub Actions (~10 min)
    Vad en pipeline är och hur den byggs upp i GitHub Actions: arbetsflöden, händelserna som startar dem, jobb och steg. En bra grund för att förstå vad som händer när ett test blir rött i CI.
  • DORA: Continuous integration (~10 min)
    Varför team som slår ihop sin kod ofta, och kör automatiska tester vid varje ändring, levererar bättre. DORA är ett forskningsprogram om hur utvecklingsteam arbetar.
  • Google: The Standard of Code Review (~10 min)
    Googles riktlinjer för kodgranskning. Målet är att kodbasen blir bättre över tid, inte att varje ändring är perfekt. Det gäller lika mycket när koden är skriven av en AI.
  • GitHub Copilot: About code review (~10 min)
    Hur en AI kan granska en pull request och föreslå ändringar. Läs med frågan: vad kan den hitta, och vad måste en människa fortfarande avgöra? Som standard räknas AI:ns granskning inte som ett godkännande.

Modul 10

Hur AI förändrar utvecklarrollen

Vad forskningen och utvecklarna själva säger

Det finns inget facit för hur utvecklarrollen förändras, men det finns data. De här tre sidorna ger olika bilder. Alla är på engelska.

  • Stack Overflow Developer Survey 2025: AI (~10 min)

  • DORA: Managing AI dependency (~10 min)
    Hur studenter som lär sig programmera sätter egna gränser för sin AI-användning, så att de fortfarande lär sig själva. Hör ihop med frågan om hur du håller din egen kunskap vid liv.

Modul 11

Etik och säkerhet

Vad du skickar, vad du får tillbaka och vem som ansvarar

Den första sidan är på svenska, de andra på engelska.

  • IMY: Personuppgifter (~5 min)
    Integritetsskyddsmyndigheten förklarar vad som räknas som en personuppgift enligt GDPR, med exempel. Bra att veta innan du klistrar in data i en AI-assistent.
  • GitHub Docs: Secret leakage risks (~5 min)
    Vad en hemlighet är, till exempel en API-nyckel eller ett lösenord. Sidan förklarar varför den finns kvar i Git-historiken även när du har tagit bort den, och att den då måste bytas ut.
  • OWASP: LLM09 Misinformation (~10 min)
    Varför en språkmodell kan hitta på saker som låter rätt. Ett av exemplen gäller kod: AI-assistenter föreslår paket som inte finns, och angripare publicerar skadliga paket med just de namnen.
  • OWASP: LLM01 Prompt Injection (~10 min)
    Hur text som en AI läser, till exempel i en fil eller på en webbsida, kan få den att göra något annat än du bad om. Läs beskrivningen och exemplen. Resten av sidan är fördjupning.

Modul 14

Praktiskt AI-assisterat utvecklingsarbete: introduktion och planering av projektuppgiften

Planera och avgränsa ett AI-assisterat projekt

I den här modulen börjar projektet på riktigt. Texterna handlar om att planera innan du bygger: hur du delar upp arbetet, hur du säger vad “klart” betyder och hur du ger AI-verktyget rätt förutsättningar.

  • Claude Code — Best practices for agentic coding (~15 min)
    Anthropics egna rekommendationer för hur man arbetar med en kodagent. Titta särskilt på arbetsgången utforska, planera, koda och committa. Det är samma ordning som din projektplan bör ha, även om du använder ett annat verktyg.
  • Atlassian — Acceptance criteria (~7 min)
    Förklarar vad acceptanskriterier är, hur man skriver dem så att de går att kontrollera och visar exempel. Direkt användbart när du ska definiera vad “klart” betyder för ditt projekt.
  • GitHub Copilot — Best practices for using GitHub Copilot (~5 min)
    Vad Copilot är bra på, när du ska använda inline-förslag och när chatt, och hur du ger rätt kontext. Rådet gäller i stort sett oavsett vilket verktyg du har valt.

Läs mer

Fler länkar om samma sak, om du vill gå djupare.

  • Martin Fowler: Yagni (~10 min)
    You aren’t gonna need it: bygg inte det du tror att du behöver senare. Fowler visar att en funktion som byggs för tidigt kostar tid och gör koden krångligare, även om den till slut behövs. Bra att ha i bakhuvudet när du skriver Utanför scope.
  • Scrum Guide: Definition of Done (~3 min)
    Ett kort avsnitt om att bestämma i förväg vad “klart” betyder, så att det inte går att diskutera efteråt. Samma tanke som när du skriver acceptanskriterier för ditt projekt.
  • GitHub Docs: Quickstart for repositories (~5 min)
    Hur du skapar ett repo på GitHub och gör din första ändring, både i webbläsaren och från terminalen. Bra om du vill ha projektet på GitHub från början.

Modul 15

Praktiskt AI-assisterat utvecklingsarbete: handledning

Granska kod du inte skrivit själv

Kod som AI:n genererat ska granskas på samma sätt som kod från en kollega. Två texter som visar hur ett vanligt granskningsarbete går till.

  • Google Engineering Practices — What to look for in a code review (~10 min)
    Googles beskrivning av vad en granskare ska titta på: om ändringen gör det den ska, hur den är designad, om testerna räcker, och om namn, kommentarer och dokumentation är begripliga. En bra checklista att ha bredvid dig när du läser en diff.
  • GitHub Docs — Reviewing proposed changes in a pull request (~5 min)
    Steg för steg hur du granskar ändringar fil för fil och lämnar kommentarer. Även när du jobbar ensam är arbetssättet användbart: läs din egen diff som om någon annan hade skrivit den.

Repetera

Har du ännu inte lagt en instruktionsfil i ditt projekt? Gå tillbaka till läsanvisningarna för modul 02 (AGENTS.md, CLAUDE.md och Copilots repository instructions). Det är den enklaste förbättringen du kan göra i den här modulen.

Läs mer

Fler länkar om samma sak, om du vill gå djupare.

  • Pro Git: Recording Changes to the Repository (~10 min)
    Pro Git är Gits officiella bok, gratis på nätet. Läs avsnitten Viewing Your Staged and Unstaged Changes och Committing Your Changes: hur du ser exakt vad som har ändrats med git diff, och hur du sedan sparar ändringen.
  • Google: Writing good CL descriptions (~10 min)
    Google kallar en ändring för CL. Sidan visar vad ett bra meddelande till en ändring innehåller: en kort första rad om vad ändringen gör, och sedan varför. Samma råd gäller ditt commit-meddelande.

Modul 16

Praktiskt AI-assisterat utvecklingsarbete: handledning

Refaktorisera med ett skyddsnät

Båda texterna handlar om samma sak: du ska kunna ändra kod utan att behöva hoppas att allt fortfarande fungerar. Därför kommer testerna först.

  • Martin Fowler — Definition of Refactoring (~3 min)
    En kort och exakt definition av vad refaktorisering är, och framför allt vad det inte är: att ändra strukturen utan att ändra beteendet. Bra att ha i bakhuvudet varje gång du instruerar AI:n att “städa upp”.
  • VS Code — Test existing code with AI (~5 min)
    Hur du genererar, kör och rättar tester med Copilot i VS Code, och hur du ger instruktioner så att testerna följer projektets stil. Principen är densamma i andra verktyg.

Repetera

Felsökning från modul 03 är fortfarande aktuell. Titta om på Claude Code — Common workflows och Learning to debug with GitHub Copilot med frågan: ber jag om hypoteser, eller bara om en fix?

Läs mer

Fler länkar om samma sak, om du vill gå djupare.

  • Michael Feathers: Characterization Testing (~10 min)
    Idén med karakteriseringstester kommer från Michael Feathers. Här visar han hur du skriver tester som fångar vad koden faktiskt gör i dag, inte vad den borde göra. Exemplet är i Java, men arbetssättet fungerar i alla språk.
  • Anthropic: Towards understanding sycophancy in language models (~5 min)
    En kort sammanfattning av en studie: AI-assistenter håller ofta med användaren, även när svaret då blir fel. Läs den innan du provar att fråga “Är du säker?” i övningen. Hela studien finns länkad från sidan.

Modul 17

Praktiskt AI-assisterat utvecklingsarbete: handledning

Tester med AI

AI skriver tester snabbt. Frågan är om testerna faktiskt kontrollerar något.

  • GitHub Docs — Copilot Chat cookbook: Testing code (~5 min)
    Exempel på prompts för att generera enhetstester, skapa mockar, skriva end-to-end-tester och uppdatera tester när koden ändras. Använd dem som utgångspunkt, och testa sedan testerna som i modulens övning.

Säkerhet när agenter läser text

En agent läser filer, webbsidor och felmeddelanden. Allt det kan innehålla instruktioner som inte kommer från dig.

  • OWASP — LLM01: Prompt Injection (~10 min)
    Förklarar skillnaden mellan direkt och indirekt promptinjektion och hur man kan begränsa skadan. Läs den med övning 4 i åtanke, där du testar vad din egen agent gör med oväntad text.
  • Anthropic — Building effective agents (~30 min, skumma)
    Har du redan läst den under agentmodulerna (modul 07) räcker det att titta om på avsnittet om när en agent är rätt val och när ett enklare arbetsflöde räcker. Bra utgångspunkt när du ska motivera hur stor frihet din agent fick.

Läs mer

Fler länkar om samma sak, om du vill gå djupare.

  • Stryker: Introduction (~5 min)
    Mutationstestning förklarad: ett verktyg lägger in små fel i koden, och om testerna ändå är gröna har felet “överlevt”. Det är samma sak som du gör för hand när du saboterar koden i övningen. Stryker finns för JavaScript, TypeScript, C# och Scala, och andra språk har egna verktyg.
  • Keep a Changelog (~10 min)
    Hur en bra ändringslogg ser ut: den senaste versionen först, ändringarna sorterade efter typ, och skriven för människor. Sidan förklarar också varför en kopia av commit-historiken inte är en ändringslogg. Bra att läsa om din agent ska sammanfatta commits.
  • GitHub Docs: About READMEs (~5 min)
    Vad en README brukar innehålla: vad projektet gör, varför det är användbart, hur man kommer igång, var man får hjälp och vem som underhåller det. Använd listan när du kontrollerar den README som AI:n skrev.
  • OWASP: LLM06 Excessive Agency (~10 min)
    Vad som kan gå fel när en agent har fler verktyg, fler behörigheter eller mer frihet än uppgiften kräver. Läs avsnittet om hur risken minskas: ge agenten så lite behörighet som möjligt, och kräv ditt godkännande för det som har stora följder. Hör ihop med prompt injection från Modul 11.
